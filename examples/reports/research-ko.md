# 첫 주문 인터뷰·과업 시험 리서치 보고서

이 보고서의 출처·발췌·수집 기록·gate 결과는 모두 만든 fixture 데이터입니다. 실제 게시글·사람·이름·인용은 사용하지 않았습니다. 실제 검색·제품 시험·gate 실행도 하지 않았습니다. 자료의 실제 연구 등급은 synthetic/E입니다. 본문의 supported_* 상태는 보고서 형식을 보여주는 설명용 값입니다. 작성일: 2026-10-01.

## 결론

1. **C-01 · supported_high / 근거 충분(높음), fixture 결과.** 할인과 배달 비용을 함께 해석하며 결제액을 다시 확인했다고 적은 경험이 두 fixture 계열에 있습니다. “배달 비용을 더하니 합계를 다시 계산했어요.” (fixture 발췌; 작성자 진술, 사실 여부 미확인). 출처: fixture-게시판-A, 2026-09-22, SRC-FX-01.
   Counter: qualifies - 같은 화면에서 합계를 확인한 사례도 있어 모든 주문의 재계산 부담으로 일반화하지 않습니다. 검색어 “배달 비용 쿠폰 총액 한눈에 확인 성공”, Q-03/CTR-01, SRC-FX-05.
2. **C-02 · supported_medium / 근거 충분(보통), fixture 결과.** 요청을 적은 뒤 메뉴를 다시 확인하고 같은 요청을 재입력했다고 적은 경험이 한 계열의 두 독립 단위에 있습니다. “메뉴를 바꾸고 요청을 다시 적었어요.” (fixture 발췌; 작성자 진술, 사실 여부 미확인). 출처: fixture-게시판-A, 2026-09-23, SRC-FX-03.
   Counter: qualifies - 앞 화면으로 가지 않은 주문에서는 요청이 남았다는 사례가 있어 화면 이동 조건을 분리합니다. 검색어 “요청사항 유지 한 번에 주문 성공”, Q-07/CTR-02, SRC-FX-06.

**다음 행동**

1. 결제액 해석 시험을 먼저 예약합니다(C-01). 정상 쿠폰·오타 복구 뒤 메뉴값, 배달 비용, 할인액과 총액을 설명하는 기록이 확신을 높입니다.
2. 요청 재입력 인터뷰와 화면 이동 시험을 예약합니다(C-02). 이동·쿠폰·주소 오류 직후 값과 최종 수신 데이터의 대조가 원인 판단을 돕습니다.

**수집 범위:** 설명용 fixture 문서 8개, 약관 제한·회원 접근 각 1개, 비공개 채널 1개 제외; 실제 제품 동작·사용자 비중·보조기술 경험은 확인하지 않았습니다.

## 발견

### 결제액 해석을 첫 시험으로 잡습니다

C-01의 fixture 상태는 supported_high입니다. 보고된 행동은 할인액과 배달 비용을 함께 보며 합계를 다시 확인하는 것입니다. 이 근거로 쿠폰 오류나 가격 정책의 원인을 확정할 수 없습니다. 다음 시험은 결제 전 총액과 항목별 금액을 한 번에 설명할 수 있는지 확인합니다. SRC-FX-05의 조건도 함께 제시해, 같은 화면에 비용이 있을 때의 설명과 비교합니다.

### 요청을 적은 뒤 메뉴를 재확인하는 상황을 분리합니다

C-02의 fixture 상태는 supported_medium입니다. 보고된 행동은 요청 입력→메뉴 재확인→요청 재입력입니다. 실제 제품이 값을 지웠는지, 작성자가 다른 초안으로 이동했는지는 확인하지 않았습니다. 화면을 오가지 않는 조건과 이동하는 조건을 따로 시험하고 각 단계의 요청 값을 기록해야 합니다. 두 세그먼트는 같은 사람이 겪을 수 있는 행동 조건입니다.

## 세그먼트

### SEG-01 · 쿠폰 적용 뒤 실제 결제액을 다시 확인하는 상황

- **상황:** 메뉴를 고른 뒤 쿠폰을 적용하고 배달 비용을 함께 해석함(C-01, supported_high; fixture).
- **과업:** 결제 전에 총액과 항목별 금액을 설명하고 주문 여부를 정함(C-01, supported_high; fixture).
- **불편 지점:** 할인 문구를 읽은 뒤 합계를 다시 계산하거나 확인했다고 적음(C-01, supported_high; fixture).
- **근거 상태:** SRC-FX-01·02의 두 fixture 단위·두 계열. 반대 사례 SRC-FX-05가 있어 모든 할인 경험으로 넓히지 않음. 실제 제품으로의 전이는 미검증.
- **비중:** `null`. 이 상황의 모집단·분모·기간이 맞는 측정 출처 없음.
- **모르는 것:** 발생 빈도, 실제 결제 화면, 쿠폰 산식, 기기·입력 조건과 사용자 비중.
- **인터뷰 모집 조건:** 최근 첫 주문에서 쿠폰을 직접 입력하고 결제액을 확인한 사례를 설명할 수 있는 사람. 선별 질문은 마지막 확인 화면과 확인한 항목을 묻음.
- **인터뷰 질문:** “마지막 주문에서 예상한 금액과 화면에서 확인한 금액을 차례로 설명해 주세요.” “확인한 뒤 무엇을 했나요?” “합계를 다시 계산할 필요가 없었던 주문은 어떤 화면이었나요?” 질문은 제안 문구임.

### SEG-02 · 요청 입력 뒤 메뉴를 재확인하는 상황

- **상황:** 가게 요청을 적은 뒤 메뉴나 설명을 다시 확인함(C-02, supported_medium; fixture).
- **과업:** 재확인 후 같은 요청을 유지하며 주문을 끝냄(C-02, supported_medium; fixture).
- **불편 지점:** 돌아온 뒤 같은 요청을 다시 적었다고 보고함(C-02, supported_medium; fixture).
- **근거 상태:** SRC-FX-03·04의 두 fixture 단위·한 계열. SRC-FX-06의 이동 없는 조건을 함께 다룸. 현재 제품의 값 유실은 미검증.
- **비중:** `null`. 적합한 측정 출처 없음. SEG-01과 겹칠 수 있음.
- **모르는 것:** 실제 이동 경로, 초안 교체·새로고침 여부, 입력 복원 규칙과 최종 수신 데이터.
- **인터뷰 모집 조건:** 최근 요청을 입력한 뒤 메뉴를 다시 보고 주문한 사례를 설명할 수 있는 사람. 요청 내용을 수집할 때는 개인 정보를 제외함.
- **인터뷰 질문:** “요청을 적은 뒤 어느 화면으로 갔나요?” “돌아와서 무엇을 확인했나요?” “다시 적지 않아도 됐던 주문에서는 무엇이 달랐나요?” 질문은 제안 문구임.
