# UI QA 결과 요약

저장된 페이지 10개를 360x780(터치)과 1440x900에서 위에서 끝까지 훑고, 스캔 후보를 캡처 픽셀로 하나씩 확인했다. 최종 10건을 보고한다. 페이지당 건수는 p01 1, p02 0, p03 0, p04 1, p05 1, p06 3, p07 1, p08 1, p09 1, p10 1이다.

가로 스크롤이 생기는 페이지는 p01(586px)과 p08(377px)이다. p01은 스크린샷 두 장이 572px, 516px 폭으로 고정되어 있고, p08은 이메일 입력과 텍스트 영역이 content-box 폭 계산 때문에 360.66px로 그려져 오른쪽으로 17px 넘친다.

눈에 띄는 겹침은 p07 히어로의 두 버튼이다. 휴대폰 폭에서 UTILITIES와 COMPONENTS가 17.4px 겹쳐 흰 알약이 첫 버튼 아래쪽을 덮는다. p06 상단 내비게이션은 마지막 항목 'Form elements'가 화면 오른쪽에서 잘려 'Form elem'으로 보이고, 첫 항목 Bahunya만 4px 위로 떠 있다.

표 관련 문제는 세 곳이다. p09의 숫자 표는 셀 여백이 1px이라 값이 '1601103.902.62'처럼 붙고, p04 표는 스크롤 상자 폭이 268px로 본문 315px보다 좁아 세 번째 열이 잘린 채 보인다. p06의 표는 다섯 번째 열 머리글이 'Tabl'에서 끊긴다.

p05의 체크박스와 라디오 7개는 라벨 첫 줄 중심보다 6px 아래에 놓여 있다. p10의 메뉴 버튼은 아이콘 폰트가 적용되지 않아 'listview' 텍스트가 32x32 상자 안에서 잘린다.

스캔이 올린 후보 중 p02 링크 겹침, p04와 p09의 h2 간격, p06 aside 겹침과 인용문 정렬, p10의 내비게이션 텍스트 겹침은 픽셀에서 재현되지 않아 제외했다. p10 항목들은 화면 밖 슬라이드 메뉴 아래에 깔린 글자였고, p02 링크는 여러 줄로 정상 줄바꿈된 밑줄이었다.

검증 범위는 Chromium 렌더링과 두 뷰포트에 한정한다. Safari, 실제 기기, 스크롤 상자 내부 이동 후 상태는 확인하지 않았다.
