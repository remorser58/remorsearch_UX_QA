기존 조사 문서를 논문 원문과 최신 공식 기술 문서에 대조해 다시 검토했습니다.

기존 조사 문서는 과거 기록으로 보존합니다. 당시의 snippet/recalled 표시는 이번 갱신으로
검증된 근거로 승격하지 않습니다.

## 출처를 확인해 바로잡은 내용

- UEyes와 MobileHCI 연구는 실험실에서 정적 화면을 관찰했습니다. 화면 위치에 따른 경향만으로
  목적이 있는 과제 수행 중의 확률을 보정할 수 없습니다. UEyes의 정정은 scanpath 평가 표에
  관한 것입니다. 공개 파일에서는 수정된 로그의 manifest를 확인하지 못했습니다.
  fixation 네 번에 공통으로 적용할 시간값은 없습니다.
- HCEye는 인지 부하가 정적 강조와 동적 강조에 미치는 영향이 서로 다르다고 보고했습니다.
  나이·저시력·인지 부하에 같은 계수를 적용하는 것은 프로젝트의 민감도 분석용 가정입니다.
  집단에서 검증된 계수로 보고할 수 없습니다.
- CSS 글자 크기는 em 기준입니다. x-height로 정의한 임계 글자 크기, NASA의 대문자 높이,
  XAG의 ascender부터 descender까지의 body 높이, Apple 플랫폼의 point는 의미가 다릅니다.
  이번 검토에서는 적용 조건에 맞는 측정 원문에서 ISO의 16-arcminute과
  고령 한국어 독자의 글자 크기 수치를 확인하지 못했습니다.
- WCAG 텍스트 간격 검사는 사용자가 간격을 바꾼 뒤에도 내용과 기능을 유지하는지 확인합니다.
  해당 수치를 기본 스타일에 적용할 의무는 없습니다. 선호하는 화면 비율을 접근성 규칙으로
  사용할 근거도 없습니다. 창의 폭과 높이가 달라져도 과제를 수행할 수 있는지 검사해야 합니다.
- Ng 등의 짐을 든 조건 연구는 터치 오차의 평균 절대 거리를 보고했습니다.
  그 값을 축별 SD의 배수로 사용할 근거는 없습니다. Yamanaka와 Usuba는 on-screen-start 과제에서
  dual-Gaussian 구조를 뒷받침하면서 계수를 다른 조건으로 옮겨 쓸 때의 한계를 보여 줬습니다.
  이동거리만으로 그 한계를 설명할 수 없습니다. 직사각형 목표에 min(W,H)를 적용하는 것은
  평가된 모델이며, 그 자체를 버그로 단정하지 않습니다.
- WCAG의 시간 제한 예외를 검토할 때는 같은 정보나 기능을 시간 제한 없이 이용하는 경로를
  확인해야 합니다. 버튼 이름만으로 동등한 복구 경로를 확인했다고 할 수 없습니다.
  FFitts에는 관측한 터치 종점의 SD가 필요하며 명목 목표 너비로 그 관측값을 대신할 수 없습니다.
  이 두 항목은 후속 수정 후보로 기록했으며 수정 완료 항목에 포함하지 않습니다.

## 외부 시선 데이터 실험

REV 평가는 변경하지 않은 `2d12bc6` 소스로 진행했으며 스킬의 Git blob 220개를 검증했습니다.
기존 합성 검사 입력도 보존했습니다. 집계 결과와 독립적으로 확인한 계산은 남겼고,
원시 참가자 ID, 이미지, 그 자료에서 만든 지도는 공개하지 않았습니다.

UEyes는 공식 CC-BY-4.0 Zenodo 배포본에서 제한된 ZIP 구간만 내려받는 방식으로 접근했습니다.
이미지 네 장과 로그 한 개로 수행한 예비 실험에서는 좌표를 해석하는 두 가지 방식에 따라
위치 요소와 이미지 요소를 비교했습니다. 이 실험으로 전체 DOM 모델을 평가할 수는 없습니다.
이후 학습·테스트 실험은 클라우드 네트워크가 나머지 다운로드를 차단해 중단했습니다.
학습용 이미지 여덟 장에는 로그가 있었고, 새 테스트 이미지는 로그를 확보하지 못했습니다.
prior를 학습하지 않았으며 누락된 점수를 0으로 대체하지 않았습니다.

별도로 확보한 MobileHCI 아카이브에는 스크린샷 193장, 저자가 제공한 fixation map과
밀도 지도, 로그 30개가 있었습니다. 원시 좌표와 기록 시간에 관한 가정만으로는 보정된 휴대폰
viewport를 복원할 수 없어 원시 이벤트를 이용한 학습도 중단했습니다.
별도로 조건을 고정한 추가 검증에서는 저자가 배포한 **전체 모니터** 지도만 평가했습니다.
모두 1920×1080이었으며 정해진 규칙에 따라 이미지를 학습/테스트 154/39로 나눴습니다.
이번 분할은 독립적으로 만든 분할입니다. 논문의 원래 분할은 확보하지 못했습니다.
휴대폰 화면 부분을 잘라 평가한 결과로 표시하지 않습니다.

추정한 구간으로 사용할 수 없습니다. 자극을 중앙에 배치한 조건과 주변의 검은 영역이

사람의 과제 수행 예측 개선을 정당화할 수 없습니다.

## 구현 비교

이 조사를 반영해 엔진에 들어간 변경은 다음과 같습니다.

- 시선 계산은 같은 시각 영역의 중복 DOM 표현을 하나로 취급하고 서로 다른 조작은 보존합니다.
  물리 화면 크기·거리·가로세로 배율로 두 시선 벡터 사이 각도를 계산합니다.
  시선 시작점과 눈의 화면 투영점은 측정하지 않은 가정으로 명시합니다.
- 조상에 잘리거나 회전해 실제 모양을 확정하지 못하는 요소는 시선 계산에서 판정을 보류합니다.
  `transform: rotate()`와 개별 `rotate` 속성, 회전한 조상을 같은 방식으로 처리합니다.
  버튼의 원래 크기와 기존 도달거리 검사용 사각형은 유지합니다.
- 조작 뒤 입력란에 초점이 이동하고 오류 메시지가 ARIA로 직접 연결된 경우 해당 메시지의
  기준점을 보정합니다. 서로 다른 기준점의 알림으로 오류 경고를 억제하지 않습니다.
  실제 시선 이동을 관측했다고 표시하지 않습니다.
- 글자 간격을 바꾸거나 창 높이를 줄인 복제 화면에서 새로 접근할 수 없게 된 내용을 검사합니다.
  폭·DPR·비교 조건과 캡처 해시를 기록하고, 원본 과업 화면·입력·초점·저장 상태를 보존합니다.
  스크롤로 도달하는 내용은 손실로 세지 않습니다.
- CSS em과 구분되는 글자 본문 높이·대문자 높이·x-height를 Canvas로 추정합니다.
  XAG 비교에는 해당 본문 높이를 사용합니다. 혼합 글꼴·변형·비공개 텍스트 등 지원하지 않는
  경우에는 측정값을 남기지 않습니다. DOM 픽셀 실측과 글꼴 대체 확인의 한계도 기록합니다.

고정한 독립 검증 13개 사례는 `853134f` 통합 버전에서 모두 통과했습니다.
새 브라우저 실행 10회, 저장 캡처 51개(원본 11개·보조 40개)를 확인했으며,
시선 계산을 켠 상태에서도 보조 캡처가 일반 과업의 판정을 바꾸지 않았습니다.
이후 `efecdb3`의 변경은 회전 속성 처리와 테스트 두 파일입니다.
같은 회전 화면의 수정 전후 재현과 별도 설치 위치의 브라우저 검사 182개가 통과했습니다.
일부 노드의 `unsupported_text_metrics`는 그대로 남겼습니다.

## 같은 개발 녹화의 비교

기준 버전 `2d12bc6`, 중간 버전 `90a1474`, 통합 분석 버전 `853134f`를 동일한 dev-2 녹화로
비교했습니다. 녹화 12개 중 완료 8개·실패 4개를 유지하고, 입력 파일 1,845개의 해시를
실행 전후 확인했습니다. 시나리오·정답·판정 임계값은 바꾸지 않았습니다.
`efecdb3`에서는 이 녹화를 읽는 분석 코드와 스키마가 바뀌지 않았습니다.

독립 실험 17회로 세지 않으며, 위의 동일 입력 비교와 구분합니다.

조건 식별 목표도 충족하지 못했습니다. 이 결과는 보존합니다. 당시의 시나리오·정답·녹화

개발 녹화에는 새 간격·창 높이·글자 메타데이터가 없어 해당 기능은 위의 별도 캡처로 검증했습니다.
